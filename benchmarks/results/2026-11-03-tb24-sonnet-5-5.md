# TB24: QQ against Claude Code, Codex and OpenCode on Sonnet 5.5

Run on 2026-11-03. Per-trial data: [`2026-11-03-tb24-sonnet-5-5.csv`](2026-11-03-tb24-sonnet-5-5.csv).

## Setup

- Model: `us.anthropic.claude-sonnet-5-5` through the operator's LiteLLM
  gateway (Bedrock behind it), priced at the gateway's own rates: $2.20 input,
  $11.00 output, $0.22 cache read, $2.75 cache write per million tokens.
- Tasks: 24 Terminal-Bench 2 tasks with a 900 s agent limit: 16 medium
  (adaptive-rejection-sampler, build-cython-ext, build-pmars, chess-best-move,
  crack-7z-hash, db-wal-recovery, gcode-to-text, git-multibranch, kv-store-grpc,
  largest-eigenval, merge-diff-arc-agi-task, polyglot-c-py, query-optimize,
  raman-fitting, sqlite-with-gcov, vulnerable-secret) and 8 hard
  (cancel-async-tasks, configure-git-webserver, fix-code-vulnerability,
  password-recovery, polyglot-rust-c, sparql-university, write-compressor,
  headless-terminal).
- One attempt per task, two concurrent trials per harness, Harbor 0.20.0.
- QQ: source `accfbf0e` (the code-mode branch, PR #558), musl release build,
  `--approval full --timeout-seconds 900 --max-turns 200 --max-cost-usd 3`,
  delegation and audit off. Three arms: `tool_surface: direct` (M0),
  `code_python` (M1), `code_javascript` (M2).
- Reference harnesses: Harbor's built-in `claude-code`, `codex` and `opencode`
  adapters via `benchmarks/harbor/compare/run-reference.sh`. OpenCode went to
  the gateway's Anthropic endpoint because its OpenAI path sends
  `prompt_cache_key`, which the gateway's Bedrock backend rejects; its results
  then carry no cost.

Pass rates differ by two tasks at k=1 and are noise. Every harness failed
configure-git-webserver, crack-7z-hash, polyglot-rust-c and
vulnerable-secret. Five QQ trials (crack-7z-hash in every arm,
password-recovery in M1 and M2) ended on turn 1 with "stopped by a content
filter" from the gateway; they report no usage and count as $0 here.

Code mode did not batch: M1 made 204 child calls from 187 `run_code` calls
and M2 210 from 181, about 1.1 per script, and turns stayed at 203–208 against
M0's 208.

## Why QQ costs about 2×

Input is not the gap: QQ direct sent fewer input tokens than Claude Code
(2.62 M vs 3.07 M) with a similar uncached share (191 k vs 189 k). Output is:
172 k against 79 k, and output is 5× the input price, so output alone is about
$1.89 of M0's $2.85.

The output is concentrated. Two tasks hold 91 k of M0's 172 k output tokens
and $1.39 of its $2.85:

| Task | QQ out | Claude Code out | Codex out | QQ $ | Claude Code $ |
| --- | --- | --- | --- | --- | --- |
| adaptive-rejection-sampler | 51.8 k | 12.8 k | 4.3 k | 0.661 | 0.186 |
| gcode-to-text | 39.6 k | 2.6 k | 2.3 k | 0.730 | 0.062 |
| the other 22 | 80.5 k | 63.8 k | 73.8 k | 1.46 | 1.31 |

Leads for the investigation, from the M0 traces in
`target/qq-eval/jobs/tb24-m0/*/agent/qq-trace.jsonl` (not committed):

1. **Unaccounted output.** QQ's turns report 172 k output tokens but carry
   about 154 k characters of visible text and tool arguments, roughly 38 k
   tokens. `reasoning_tokens` is 0 on every turn and no reasoning deltas
   reached the trace. QQ sent no `reasoning_effort` (the trial record has
   none, and `openai_chat.rs` only sends it when one is configured), so find
   out whether the gateway or Bedrock enables thinking by default for this
   model and bills it without breaking it out, or whether the count is
   something else. Compare the request body QQ sends with Claude Code's on
   the same gateway, and the gateway's spend log for one QQ turn.
2. **Whole-file rewrites hitting the output cap.** In
   adaptive-rejection-sampler, turns 3, 4 and 6 emitted 16 384, 19 558 and
   13 650 tokens: two `write_file` calls of about 25 k characters each, one
   cut at the 16 384 output limit and continued. Claude Code solved the same
   task in 12.8 k output tokens.
3. **Long low-yield loops.** gcode-to-text ran 36 turns with output growing to
   1–3 k tokens per turn (mostly repeated ~500-character shell scripts) and
   still failed; Claude Code and Codex passed it in about 2.5 k tokens.
4. **QQ is faster.** Median wall time on passes is 82 s against about 129 s,
   so any fix should be checked against wall time as well as cost.

## Reproduce

```sh
export LITELLM_API_KEY=... LITELLM_BASE_URL=https://GATEWAY/v1
TASKS=(); for n in adaptive-rejection-sampler build-cython-ext ...; do TASKS+=(-i "terminal-bench/$n"); done
QQ_CONFIG_CONTENT="$(cat ARM.ron)" cargo xtask eval run --arm M0 \
  --model litellm/us.anthropic.claude-sonnet-5-5 --dataset terminal-bench/terminal-bench-2 \
  --job-name tb24-m0 --target x86_64-unknown-linux-musl --n-attempts 1 --n-concurrent 2 \
  --timeout-seconds 900 --max-turns 200 --max-cost-usd 3 "${TASKS[@]}"
benchmarks/harbor/compare/run-reference.sh claude-code us.anthropic.claude-sonnet-5-5 tb24-claude-code \
  --n-concurrent 2 "${TASKS[@]}"
benchmarks/harbor/compare/summarize.sh target/qq-eval/jobs/tb24-*/
```

`ARM.ron` is `benchmarks/harbor/eval-config.ron` with the real gateway
`base_url`, a `us.anthropic.claude-sonnet-5-5` model entry
(`reasoning: true`, `context_window: 1000000`, `max_output_tokens: 128000`,
pricing 2200 / 11000 / 220 / 2750 nanos per token), and the `delegation`,
`audit` and `policy` sections of the matching `benchmarks/arms/m*.ron` from PR #558. QQ
still capped each turn at 16 384 output tokens (the trace's
`max_output_tokens`).

`cargo xtask eval report` rejects these traces with "has no output token
limit": the trial record carries `max_output_tokens` only when
`--max-output-tokens` is set, so the figures above were computed from
`result.json` and the traces directly.
