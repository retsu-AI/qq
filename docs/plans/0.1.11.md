# v0.1.11: a fast TUI you can work in

v0.1.11 changes only the TUI, and its core is a redesign of the interface
(section R). The goal is that a user can run many sessions from one `qq`
window and stay oriented: the screen shows what needs them and little else,
switching to another session takes a couple of keys, nothing waits on the
network or the disk in front of the user, and copying the agent's output
gives exactly the text they selected.

Parent issue: [ENG-1104](https://linear.app/retsu-ai/issue/ENG-1104).

This plan replaces the TUI focus plan (ENG-1067) and its stacked PRs #354,
#356, #358, #360 and #363, which are closed. What they got right is kept
below under [Kept from the closed PRs](#kept-from-the-closed-prs). Issues
carry assignments and verification. Remove a section when it ships.

Out of scope: attaching to remote daemons, a saved server list, sessions
from other workspaces, and pairing (ADR-0015). v0.1.12 is about parallel
work in the TUI and CLI ([plan](0.1.12.md)). No protocol change, no store
change, and no new crate in `Cargo.lock` are expected; a section that
finds it needs one says so in its PR.

## Rules for every section

1. **Show it only when it matters.** A surface appears when it has
   something to say and goes away when it doesn't. One fact is shown in one
   place.
2. **Nothing blocks a frame.** No file walk, process spawn, clipboard write
   or network call runs between an input event and the frame that answers
   it.
3. **The keyboard is enough; the mouse is a shortcut.** Every mouse action
   has a key.
4. **Copies are only text.** A copy never contains another pane's cells,
   borders, gutters, padding or a split grapheme.

These are the guarantees from the closed plan, kept as hard requirements
with a regression test each:

- **Audits are not user-facing.** No list, count, picker, navigation key,
  attention surface or fallback focus offers a session known to be under
  an audit (`SessionPurpose::Audit`), and none acts on one. A task agent
  whose audit ancestor is not loaded stays visible until ENG-1080 adds a
  lineage marker.
- **Answers go to the call shown.** `Alt-A`/`Alt-D` answer only an
  approval whose title is on screen, never an `ask_user` hold, and a forced
  focus move drops a half-typed answer instead of sending it elsewhere.
- **No slower renders.** See section B.

## Evidence

Read from `main` at `b6cdf6ac`:

- **Copy.** The TUI draws on the primary screen (`TerminalGuard::enter`,
  `crates/qq-tui/src/terminal.rs:390`) with mouse capture on
  (`terminal.rs:433`). Only the wheel is handled
  (`crates/qq-tui/src/app.rs:1306`); a drag does nothing. Every frame row is
  one full-width line with the rail and inspector pasted in and padded with
  spaces (`crates/qq-tui/src/view.rs:304`). The terminal knows nothing about
  panes, so Shift-drag (which bypasses capture) copies rail names, `│`
  borders and trailing spaces, and output from before `qq` started is in
  the same buffer. There is no clipboard or OSC 52 code. `/mouse` says
  "click focuses" (`app.rs:1728`), which is false.
- **Ctrl-C quits at once** (`app.rs:1334`). Users reach for it to copy.
  When this `qq` owns the server, quitting cancels every run on it.
- **Startup.**
  - Config, TUI settings and themes are loaded in a `spawn_blocking` task
    that is awaited before the terminal is entered (`src/main.rs:715`).
  - Bootstrap then makes three to four sequential requests before the
    transcript appears (`crates/qq-client/src/interactive.rs:459-531`):
    `resolve_workspace`, a snapshot, an optional `CreateSession`, and a
    second snapshot only to pre-warm four bodies. The model catalog loads
    after that.
- **Blocking the loop.** Mention resolution and `@` completion are awaited
  inline in the event loop (`terminal.rs:286-315`). A large tree stalls
  input until the walk ends.
- **Per-frame work.** The whole frame model is rebuilt on every draw.
  - Changed rows are rewritten in full (`view.rs:142-181`).
  - `rail_entries` walks every session on every frame
    (`crates/qq-tui/src/view/sidebar.rs:75`).
  - These costs are inferred from the code, not measured; B1 measures them.
- **Switching.**
  - `/sessions` (or `Ctrl-T`) is a tree-order list with subsequence search
    on titles (`crates/qq-tui/src/app/pickers.rs:945`).
  - The rail can't be clicked.
  - One task that fans out to 20 agents adds 20–40 rail rows and 20 picker
    rows.
  - A cold session's body is requested only after focus moves to it
    (`app.rs:1859`).
- **Noise.**
  - The inspector's `Auto` state takes 40–80 columns at 160+ to say
    `Nothing expanded`.
  - One child approval is named three times in one frame.
  - The rule always shows `? help ^K commands ^O detail`.
  - Completed runs print `✓ 0.0s · ttft 0.0s`.
  - Collapsed reasoning carries an `Alt-R` suffix.
  - `Ctrl-T` "session navigator" and `Ctrl-\` "session sidebar" are
    different things with nearly the same name.
- **Size.** `qq-tui` has 44 registry commands, 27 slash spellings and about
  35 chords. The crate is 33k lines, 13k of them tests. 60 text goldens and
  a render bench (`crates/qq-tui/benches/render.rs`) pin it.

The design below keeps what works elsewhere and adds what QQ needs:

- Selection anchored to source cells, so copies skip borders and rejoin
  wraps.
- Copied text built from content lines, not the screen.
- A clipboard that shows "Copied!" only after a confirmed write and says
  when a copy is unconfirmed.
- Pickers that rank name matches above body matches.
- Next-unread switching across sessions.
- OSC 52 stripped from model and tool output.

The selection model, the block cursor and the switcher are QQ's own.

## R. Redesign the interface

Issue: [ENG-1110](https://linear.app/retsu-ai/issue/ENG-1110).

Today's frame is a dashboard: a header row, a bordered rail drawn the full
height even when it lists three rows, `▌ YOU` and `QQ` labels on every
message, a permanent hint strip, and a separate agent strip. The 120 × 40
`golden-path` golden spends 27 of its 40 rows on empty rail border. R
replaces that with one visual language. A, C, D and E build on it.

### Principles

1. **The transcript is the page.** Nothing sits above it. Every control
   lives in one dock at the bottom.
2. **Structure comes from glyphs and brightness, not boxes.** No borders
   around messages, tools or panes. Only code panels have a background
   fill, plus the selection highlight.
3. **Color means something.** Hue is used for exactly five things: you
   (`accent`), running (`info`), needs you or caution (`warning`), failed
   (`error`), and diff signs. Everything else is one of three brightness levels:
   `text`, `muted`, `faint`. Every state also has a glyph, so the screen
   still reads with `NO_COLOR` or the ANSI `terminal` theme.
4. **One place to look for state.** The rule above the composer carries
   the focused run's activity, and on its right edge whatever needs you
   anywhere. There is no header row, no separate strip and no second
   spinner.
5. **Finished work gets quieter.** While a turn runs, every tool row is
   live. When the turn settles, its routine calls fold into a single
   receipt row. Edits, failures and answers stay.
6. **One page, anchored left.** The transcript and the dock share one
   page: a 2-column margin, a 2-column glyph lane (`┃ ● │ ├ ∴`), then
   text at the 100-column measure. A wider terminal never adds left
   padding or moves the page; the sessions column sits right after the
   page and the rest of the screen stays empty. Every block's text starts
   in the same column, so the eye reads one straight edge from the first
   prompt to the composer.

### Kept and QQ's own

Kept:
- the `┃` rail shared by your prompts and the composer;
- one-line tool rows with `├ └` connectors;
- selection shown by brightness;
- no header;
- hint ladders that keep the widest set of hints that fits;
- a fixed dock under a scrolling transcript in fullscreen mode;
- state carried on the rule rather than in extra rows;
- pickers and confirms that replace the composer in place, not a modal
  over the transcript;
- inverse video for changed words inside a diff line.

QQ's own:
- the **turn receipt**, which folds a settled turn's calls into one row
  summarizing files changed, commands run and duration;
- the composer rail's color warns when a session runs in **full** mode or
  can only read;
- **attention on the rule's right edge**, replacing the strip;
- a **sessions column without borders**, numbered for `Alt-1`…`9`;
- **live agent lanes** under a spawn call;
- **one dock** that hosts the composer, approvals, questions and the
  switcher, so the eye never leaves the bottom of the screen.

QQ rejects:
- an eight-segment status line and long approval prose;
- tinted tool boxes and stacked fills, an abbreviation-heavy stats row,
  and a multi-line startup header.

### The dock

From bottom to top:

- **Status line.** `title · model effort · ctx% · $cost · mode` on the
  left, and `~/workspace  branch` on the right.
  - A sub-agent shows `parent › agent` as its title.
  - Cost is hidden when it is a known zero, and the mode when it is
    `auto`.
  - `connecting` and `offline` replace the right side, in `warning`.
  - This row replaces today's top row.
- **Composer.** The rail is `┃`, followed by the input. The rail's color
  shows how much the session may do on its own: `faint` for read-only,
  `accent` for ask and auto, `warning` for full. The status line names
  the mode whenever it isn't `auto`. Multiline input repeats the rail
  on every row. A scrolled draft shows `┃↑`. There is no box and no `›`
  glyph.
- **Queued drafts.** Shown above the composer with a dotted rail `┋`, at
  most two rows each.
- **Rule.** A `─` line.
  - Left: the focused session's state glyph, then its activity and
    elapsed time, such as `◐ editing sse.rs · 14s`. When idle the line is
    plain `faint`.
  - Right: attention counts across the window (`◇ 2 need you  ^G`), the
    session count at Compact, or a notice.
  - The rule's color follows the focused session: `faint` idle, `info`
    running, `warning` waiting on you, `error` after a failure.
  - Hints come from a ladder and appear only in context, for example
    during an approval or while steering.
- **Panels.** An approval, a question, the switcher, `/models` and the
  other pickers open *in the dock*. They replace the composer and grow
  upward to at most half the body height. `Esc` puts the composer back
  with its draft intact.

### The transcript

- **Your prompt.** `┃` in `accent`, then bold `text`. Wrapped rows repeat
  the rail. No label.
- **Answer.** Markdown at the measure with a 2-column gutter. No label. A
  `▍` caret marks the streaming tail. Errors start with `✕` in `error`.
- **Reasoning.** While it streams, it shows only on the rule (`◐
  thinking · 6s`). Afterwards it is one `faint` row, `∴ 12s`, that the
  block cursor or `Alt-R` opens.
- **Tool row.**
  - Layout: glyph, a past-tense verb, the subject in `muted`, and the
    metric right-aligned in `faint`, e.g. `● Read  src/sse.rs  412
    lines`.
  - Running uses the spinner and a present-tense verb (`Reading`), with a
    live tail of at most 3 rows on a `faint` `│` rail.
  - A failure is `✕` with the exit status, and its tail stays open.
  - The duration is shown only when it is over 1 s.
- **Edit.** The row reads `● Edited src/sse.rs  +4 −1`.
  - The diff shows inline for the newest edit of a running turn: at most
    8 rows, line numbers in `faint`, signs in diff colors, and changed
    words in inverse video.
  - Older edits keep only the row until they are opened.
- **Agents.** A spawn call is a header row followed by one live lane per
  agent:

  ```
  ● Spawned 4 agents                                         ◐ 2  ◇ 1  ● 1
  ├ ◐ audit parser      reading src/parser.rs
  ├ ◇ deploy helper     wants to run cargo publish --dry-run
  ├ ◐ docs pass         editing docs/guide/tui.md
  └ ● bench             done · 3 files
  ```

  - More than 6 agents fold to the 6 most urgent plus `└ +14 more  ^T`.
  - A lane shows its agent's live activity, and `Enter` on a lane focuses
    that agent.
- **Turn receipt.** When a turn settles, its quiet completed calls
  (reads, searches, listings, successful commands) collapse into one
  row:

  ```
  ● 9 calls · read 5 · searched 2 · ran 2   3 files +18 −6   1m 04s
  ```

  - Edits and failures keep their own rows under the receipt.
  - `Ctrl-O` or the block cursor opens it.
  - This replaces `▸ Read ×2 …` and `✓ 0.0s · ttft 0.0s`. Time to first
    token appears only inside the opened receipt.
- **Spacing.** One blank row between blocks. No blank row between a tool
  row and its tail, or between lanes.

### Sessions column

- It appears at Regular and wider when there are at least two sessions.
- It is separated from the page by a 4-column gutter, with no
  border, and is 26 columns at Regular and 34 at Wide. Group labels are
  `faint` small caps (`NEEDS YOU`, `WORKING`, `RECENT`) with a blank row
  between groups.
- Each row is a number (`1`–`9`), a glyph, the title in `muted`, and an
  `↳N` agent badge. The focused row is `text` with an `accent` `▎`.
- At Wide, a second `faint` row shows the session's live activity with
  its cost right-aligned. Text that does not fit ends in `…`.
- Below Regular it disappears entirely, and its counts move to the rule.
- Behavior is section C. R sets the look.

### Theme and motion

- Add a derived `faint` role, `muted` blended halfway toward the
  background. It needs no new theme key, and themes may override it.
  `surface` stays the code-panel fill.
- One spinner (`◐◓◑◒`) on the rule and on running tool rows, on the
  existing 125 ms tick, which runs only while something on screen
  animates. No shimmer, no blinking, no paced reveal beyond the
  streaming caret.

## A. Copy exactly what you selected

Issue: [ENG-1105](https://linear.app/retsu-ai/issue/ENG-1105).

**Screen.** Enter the alternate screen (`?1049h`) and leave it on exit, so
quitting restores the user's shell untouched. On exit, print the focused
session's last answer as plain text, followed by the resume line, into the
normal scrollback. The answer that matters is then in native scrollback for
native copy, search and tmux copy mode.

**Mouse selection, from source rows.**
- A drag that starts in a transcript pane selects text in that pane only,
  clamped to its columns and body rows, however far the pointer goes.
  Selected cells repaint on the `selection` background.
- Release copies. A click without a drag copies nothing. `Esc`, any key,
  a new press, a resize, or the selected rows changing underneath clears
  the selection.
- Copied text comes from the rows the transcript laid out, not from screen
  cells. Each laid-out `Line` records:
  - how many leading cells are chrome: message rail, code gutter, list
    marker, quote rail, panel padding;
  - whether it is a soft wrap of the line before.

  The copy drops the chrome, keeps meaningful indentation, rejoins soft
  wraps, keeps hard newlines, and keeps grapheme clusters whole.
- Double-click selects a word; triple-click selects the whole block under
  the pointer (paragraph, code block, tool output). The closed plan ruled
  this out. It is in scope now because it is how most people copy one code
  block.
- The selection is painted after the frame is composed, so no transcript
  cache sees it and a frame with no selection does no extra work.

**Keyboard copy: the block cursor.** Today `Ctrl-Up`/`Ctrl-Down` move a
cursor over tool rows only.
- Widen that cursor to every block in the transcript: your prompt, each
  answer, each code block inside an answer, each tool call.
- On a block, `y` copies it: an answer as its Markdown source, a code block
  as its raw code, a tool call as its command and output.
- `Enter` still expands a tool row, and `Esc` leaves the cursor. A
  pending approval or question still claims `y`, `n` and `Esc` first.
- This replaces the tool-row cursor rather than adding a second one.

**Commands.**
- `/copy` copies the focused session's last answer as Markdown source.
- `/copy code` copies the last code block in it.
- `Ctrl-C` with a selection or a block cursor active copies and does not
  quit.

**Clipboard writes.** Writes run off the event loop with a bounded wait,
in this order:
1. A local helper when the session is local: `wl-copy`, `xclip` or `xsel`,
   `pbcopy`, or `clip.exe` under WSL. These are spawned processes, not a
   new crate.
2. `tmux load-buffer -w -` inside tmux.
3. OSC 52, always sent as well, so SSH and terminals with no helper still
   work. Inside tmux it uses DCS passthrough.

The notice says `copied 12 lines` when a helper confirmed the write. It
says `sent 12 lines to the terminal clipboard` when only OSC 52 was sent,
because QQ can't know whether the terminal accepted it. Copies are capped
at 1 MiB and say so when they are cut. Copied text has control and
escape sequences stripped, so an agent can't plant an OSC 52 or a
terminal command in someone's clipboard.

**Native selection still works.**
- Shift-drag remains the terminal's own selection.
- `/mouse` turns capture off. While it is off, the layout drops the rail to
  the strip and draws the transcript flush left with no measure inset. A
  native selection of a full row is then clean text.
- `/mouse` says what each state does, truthfully.

**Accepted when:**
- Unit tests cover chrome exclusion for every prefix kind, soft-wrap
  rejoin against hard newlines, wide and joined glyphs, the 1 MiB cap,
  escape stripping, and each clearing rule.
- An app test covers a drag in each direction, double- and triple-click,
  `y` on each block kind, `/copy`, and `Ctrl-C` copying.
- A loop test asserts the exact OSC 52 bytes, with and without tmux
  passthrough, and the confirmed and unconfirmed notices.
- The [TUI QA runbook](../runbooks/tui-qa.md) records a manual
  copy-and-paste of an answer, a code block and a selection spanning a
  wrap in Ghostty, kitty, WezTerm, Alacritty, GNOME Terminal and Windows
  Terminal. It also records tmux and SSH. Each result is recorded as
  observed, failures included.

## B. Speed: measure, then remove waits

Issue: [ENG-1106](https://linear.app/retsu-ai/issue/ENG-1106).

**B1. Baseline first.** Before any other section lands, record on one
quiet host:
- the render bench medians;
- time from exec to first painted frame;
- time to a painted transcript when attached to a warm `qq daemon`, and
  when embedding the server;
- keystroke-to-frame latency while one session streams and seven others
  stream in the background;
- switch-to-session latency for a warm body and for a cold one.

Add the missing scenes to the bench: selection paint, switcher open and
filter, and a 50-session rail with 200 agents. Startup is measured with
the QA fixture and the loopback fake provider. Raw results go under
`target/qq-perf/v0.1.11/`, following
[perf recording](../runbooks/perf-recording.md).

**B2. Remove waits in front of the user.**
- Paint the first frame (top row, empty composer, `connecting`) before
  config load and server attach. The composer accepts typing at once. A
  prompt sent before the server is ready is held and sent when it is.
- Fold bootstrap into one snapshot request that returns the session list
  and the pre-warmed bodies, and load the model catalog in parallel with
  it. If this needs a server change, the PR says so; it does not change
  the protocol.
- Mention resolution and `@` completion become effects whose results
  arrive as events. A newer query discards an older result.
- Fetch a cold session's body when its row has been highlighted in the
  switcher or rail for 100 ms, not after focus moves.

**B3. Cheaper frames.** Only what B1 shows is worth it, for example:
- cache `rail_entries` per snapshot generation instead of per frame;
- skip unchanged spans within a changed row;
- stop the animation tick when nothing on screen animates.

**Targets.** B1 sets the final numbers. These are the starting
expectations:
- the first frame is painted within 50 ms of exec;
- the transcript is painted within 150 ms when attached to a warm local
  daemon;
- keystroke-to-frame is under 16 ms at p99 with eight streams;
- switching to a warm session takes one frame, and to a cold local session
  under 100 ms.

**Accepted when:**
- B1's numbers are in the PR and the plan.
- Every later section's PR reports the render bench against B1. No gate is
  more than 5% slower; any speed-up passes. Use interleaved binaries pinned
  to one core, as the closed F1 and F6 PRs did, because sequential runs
  drift.
- The targets above are met, or each miss is listed with its number.

## C. Switch sessions in two keys

Issue: [ENG-1107](https://linear.app/retsu-ai/issue/ENG-1107).

Sessions and agents are distinct:
- A **session** is a root conversation, or an agent whose parent isn't
  loaded.
- An **agent** is a sub-agent under a loaded session.

Lists show sessions. A session's agents fold into its row.

**Rail.**
- Groups are NEEDS YOU, WORKING and RECENT. RECENT merges idle and done,
  with glyphs to tell them apart. Unseen finishes and failures stay in
  NEEDS YOU.
- Each row shows the state glyph, the title, an `↳N` agent badge with a
  working count, and inclusive spend (`accounting.inclusive`). A row is
  only as tall as it needs to be.
- An agent gets its own row only when it waits on the user, under its own
  session, or when it belongs to the focused session. Agent rows are
  capped at 6, then `+N more`.
- The rail appears only when there are at least two sessions and room for
  it; otherwise the one-row strip counts them.
- A click on a row focuses that session. The first nine rows show `1`–`9`
  in the gutter, and `Alt-1`…`Alt-9` focus them.

**One attention order.** Approvals first, then failures, then unseen
finishes, newest session first. That order feeds `Ctrl-G`, `Alt-A`/`Alt-D`,
`/attention`, the rule and the strip. Each needs only the pending
holds; a running side question counts as WORKING.

**The switcher.** `Ctrl-T` (renamed "switch session") opens one centered
list. It replaces both `/sessions` and the navigator.
- Each row shows the state glyph, the title, the age, and the last line of
  the session's latest answer. The highlighted row shows a few lines of its
  latest answer under it, from the cached body, without a request.
- Typing ranks matches:
  1. title prefix;
  2. title word prefix;
  3. title subsequence;
  4. agent title, shown as `Session › agent`;
  5. text of the latest answer.

  Ties go to the most recently active.
- `Enter` focuses. `Tab` expands or collapses a session's agents. `Ctrl-A`
  lists every agent. `Ctrl-D` deletes after a confirmation.
- When the highlighted row stops being listed, the cursor falls back to
  its session.
- On open, the cursor sits on the previous session, so `Ctrl-T Enter` goes
  back.
- `Ctrl-^` swaps to the previous session without opening anything. Many
  terminals send it as `Ctrl-6`; both are accepted, and the key is
  rebindable in `tui.ron`.
- Rows are keyed by session id, so v0.1.12's work items (open changes,
  background commands) can join the list without redesigning it.

`/sessions` and `/resume` stay as spellings of the switcher. `/agents`
opens it scoped to the focused tree. `Alt-Left`/`Alt-Right`/`Alt-Down` and
`Esc`-to-parent stay, and skip audits.

**Accepted when:**
- There are app tests for every key above, the ranking order, the cursor
  fallback, the previous-session default, the caps, the groups, inclusive
  spend, and audit exclusion.
- A `fanout` golden shows one task with 20 agents taking one rail row
  plus its needs.
- A test shows a hidden agent's stream does not wake a frame.

## D. Show less

Issue: [ENG-1108](https://linear.app/retsu-ai/issue/ENG-1108).

- **Inspector only with content.** Its `Auto` state shows only while the
  focused pane has an expanded tool call or a workspace view (`/attention`,
  `/changes`); otherwise the columns go back to the transcript. `Alt-I`
  still pins it.
- **One place per fact.**
  - A need that the rail, the strip or a child's live card already shows
    is not named again on the rule. The rule names the most urgent need
    that nothing else shows and counts the rest.
  - `related sessions` becomes one summary row.
  - The top row omits a known zero cost.
- **Quieter rule and transcript.** Section R defines the look: hints
  only in context, no permanent `^K commands ^O detail`, turn receipts
  instead of `✓ 0.0s · ttft 0.0s`, and no `Alt-R` suffix. D removes the
  code paths and settings that R makes dead, such as the `Rows`/`Folded`
  tool-detail toggle, which becomes open/close on a receipt.
- **Ctrl-C.**
  - With a selection, it copies (section A).
  - With text in the composer, it clears the composer.
  - Otherwise the first press says `Ctrl-C again to quit` and names how
    many runs will stop if this `qq` owns the server. A second press within
    two seconds quits.
- **Fewer names.**
  - `Ctrl-\` toggles the rail and is called "rail".
  - `Ctrl-T` is the switcher.
  - `/btw-new` and `/btw-cancel` become `/btw new` and `/btw cancel`.
  - `/clear` stops being a silent alias of `/new`.
  - Every removed spelling gets a one-release notice naming its
    replacement.

**Accepted when:**
- Frame tests cover the common layouts: Compact, Regular with and without
  the rail, past the agent cap, under a notice. Each shows every need
  named exactly once.
- The goldens are moved deliberately, with the reasons in the PR.
- The command and chord counts are reported before and after.

## E. A transcript that holds up at scale

Issue: [ENG-1109](https://linear.app/retsu-ai/issue/ENG-1109).

- **Find.** `Ctrl-F` searches the focused transcript, including collapsed
  tool output and reasoning. `Enter` and `Shift-Enter` step between
  matches, and the matched block opens and scrolls into view. Search runs
  over laid-out rows, off the frame path for long sessions.
- **Stay put while reading.**
  - Scrolled away from the tail, streaming never moves the view.
  - A `↓ N new` marker on the rule shows new output below.
  - `Ctrl-End` or `End` on an empty composer returns to the tail.
- **Long output.**
  - A tool call's live tail is capped at a few rows inline.
  - An expanded call scrolls inside its own block rather than pushing the
    answer off screen.

**Accepted when:** there are app tests for find across collapsed blocks, a
stable viewport during streaming, and the new-output marker, and the
`streaming_run_on_32kb` and `steady_state` bench gates hold.
