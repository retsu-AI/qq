## 0.1.6 — 2026-10-08

### Upgrading
- Contracts changed since v0.1.5 (0ver: PATCH release, ADR-0051): `PROTOCOL_VERSION` 30 → 31, `DESCRIPTOR_VERSION` 12 → 13, `STORE_SCHEMA_VERSION` 39 → 43; `CAPABILITIES_VERSION` stays 1.
- Restart any long-running `qq serve` and upgrade its clients together: a client refuses a server on a different protocol.
- The session store migrates forward on first open, and v0.1.5 cannot open it afterwards. Run `qq config paths` and locate the `data` directory; the database is `sessions.sqlite3` inside that directory, not in your current project directory. Before upgrading, stop every QQ process (`qq serve`, the TUI, and any `qq run`) and copy that database together with any adjacent `sessions.sqlite3-wal` and `sessions.sqlite3-shm` to a separate backup directory. If processes must remain running, use SQLite's consistent backup: replace both placeholders with absolute paths, verify the source file exists, then run `sqlite3 -readonly "/absolute/path/from/qq-config-paths/data/sessions.sqlite3" ".backup '/absolute/path/to/backup/sessions.sqlite3'"`. Do not run the example with a relative source path: SQLite can otherwise create an empty database. Rollback requires stopping QQ, restoring the pre-upgrade backup at the original data-directory path (without retaining migrated WAL/SHM files), and using the old binary.
- Project pack manifests now require their own exact-content trust review, including manifests discovered under `.qq/packs/` and those named by project configuration. Previously trusting a project's configuration does not automatically trust its packs. Review the TUI prompt or use `qq trust`; editing a trusted `pack.ron` requires another review before its MCP commands can start.
- Project-declared pack paths must resolve inside the repository and must not traverse symlinks. An external absolute/`..` path or a symlinked pack source now fails with `InvalidPack` or `SymlinkSource`; `qq trust` cannot override this restriction. Relocate the pack to a regular directory inside the repository, or move the external-pack declaration to your user/global configuration.
- Read sub-agents now run in the background: use `wait_agents` to await their answers and `cancel_agent` to stop them. Supervised write delegation remains approval-controlled; it is not made asynchronous by this change.

## 0.1.5 — 2026-09-29

### Upgrading
- Contracts changed since v0.1.4 (0ver: shipped as a PATCH release, ADR-0051): `PROTOCOL_VERSION` 27 → 30, `DESCRIPTOR_VERSION` 9 → 12, `STORE_SCHEMA_VERSION` 35 → 39; `CAPABILITIES_VERSION` stays 1.
- Restart any long-running `qq serve` and upgrade its clients together: a client refuses a server on a different protocol.
- The session store migrates forward on first open, and v0.1.4 cannot open it afterwards. If you might roll back, stop every QQ process first (`qq serve`, the TUI, any `qq run`), then copy `sessions.sqlite3` together with any `sessions.sqlite3-wal` and `sessions.sqlite3-shm` beside it: the store runs in WAL mode, so recent history may live in the `-wal` file until the last process closes. Or, with the processes still running, take a consistent copy with `sqlite3 sessions.sqlite3 ".backup backup.sqlite3"`.
- `reasoning_effort` values a model does not list in its known accepted set now fail at plan time with the accepted values named: for example `minimal` on GPT-6 Astra, `xhigh` on Claude 4.6, `none`/`minimal` on Anthropic. Pick an accepted value, or `default` to let the provider choose.
- `jev_approval` now follows the run's profile and applies to the next run without a restart; a profile's `jev_approval: false` turns Jev approval off for that profile.
